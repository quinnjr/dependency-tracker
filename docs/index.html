Four repos. Three different pins. None of them on 1.3.0.

It reads what you already committed

No configuration file describing your dependencies twice. Point it at the folders where you keep repositories and it walks them, reading the manifests and lockfiles that are already there. A lockfile wins over the manifest beside it, because a resolved version can be compared against a release and a range cannot.

The GitHub token is optional

Unauthenticated api.github.com allows 60 requests an hour, which one refresh of a few hundred packages spends immediately. But releases.atom is a plain feed and costs no quota at all — so feeds are the default path, and release notes work with no token.

Add a token and the notes arrive as real Markdown instead. That is the only difference. If your keyring is unavailable, the app tells you and runs without the MCP server rather than falling back to something unauthenticated.

An agent can read the same data you can

While the window is open, an MCP server runs on loopback over SSE. It works against the same store the interface renders from, so a watch an agent adds appears in the window with no polling. Ten tools:

list_watches get_watch get_release_notes search_watches add_watch add_rss_watch remove_watch mark_read snooze refresh_now

Any page in your browser can reach 127.0.0.1, so the server binds loopback only, validates Origin by exact host, and compares its bearer token in constant time before it will even route a request. Both that token and your GitHub token live in the host keyring and nowhere else.

What it does
  • One row per package Used by five repos, it is one row with five pins — enforced by the schema, not by hopeful code.
  • Release notes inline Enough of the changelog to decide whether you care, without opening a browser.
  • Starts quiet A newly added package does not dump ten years of history at you as unread.
What it doesn't
  • Open pull requests Renovate and Dependabot already do that well. This is the triage surface they don't give you.
  • Run in the background No daemon, no tray icon, no notifications. It checks when you open it or ask it to.
  • Prune emptied watches yet Drop a dependency and its row stays behind with no repos attached. Known, unfinished.
